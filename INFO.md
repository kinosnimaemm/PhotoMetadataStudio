# Metadata Studio

## Что это

Metadata Studio — локальное и облачное веб-приложение для пакетной обработки метаданных фотографий.

Пользователь может:

- загрузить до 10 фотографий;
- выбрать готовый профиль телефона и геолокации;
- создать собственный профиль;
- очистить старые метаданные;
- применить новые EXIF, IPTC и XMP-поля;
- задать последовательные имена и время снимков;
- сохранить обработанную партию.

## Как устроена обработка

Сервер написан на Node.js без тяжёлого веб-фреймворка.

Основной файл:

```text
server.js
```

Для загрузки файлов используется `Busboy`. Фотографии временно записываются в системную папку macOS или Linux.

Обработка выполняется с помощью:

- ExifTool — очистка и запись EXIF, IPTC и XMP;
- FFmpeg — пересборка JPEG и создание миниатюры;
- ZIP — упаковка облачной партии для скачивания.

Перед добавлением нового профиля старые метаданные полностью удаляются командой ExifTool `-all=`.

Результат содержит явную маркировку:

```text
CreatorTool: Metadata Studio
Description: Synthetic metadata profile applied locally; capture provenance not verified
```

Это означает, что профиль был применён программно и не подтверждает происхождение фотографии.

## Работа с партиями

- Максимум 10 фотографий.
- Максимальный размер одного файла — 80 МБ.
- Поддерживаются JPEG, HEIC, PNG, TIFF и WEBP.
- Имена могут иметь формат `IMG_XXXX`.
- Дата каждого следующего снимка увеличивается на выбранный интервал.
- ISO, выдержка и направление камеры немного меняются между снимками.
- Не сохранённые результаты автоматически удаляются через 15 минут.

## Сохранение

### Локальный режим

Кнопка сохранения открывает системное окно выбора папки macOS.

Файлы копируются напрямую в выбранную папку. Расширенные атрибуты macOS очищаются, поэтому Finder не показывает поле `Where from`.

### Облачный режим

Браузер скачивает всю партию одним ZIP-файлом. После завершения передачи временные фотографии удаляются с сервера.

Облачный сайт не может открыть нативное окно Finder на компьютере пользователя. Это ограничение браузера.

## Профили

Встроенные профили:

```text
profiles.json
```

Каталог телефонов:

```text
public/devices.js
```

Пользовательские профили сейчас хранятся в `localStorage` браузера. Они:

- отображаются первыми;
- сохраняются после перезагрузки;
- могут быть удалены;
- объединяют модель телефона, камеру и геолокацию.

В конструкторе есть готовые локации Германии, США, Европы, Дубая и Токио, а также ручные координаты.

## База данных

Для облачной версии подготовлен PostgreSQL.

Подключение:

```text
src/database.js
```

Первая миграция:

```text
migrations/001_initial.sql
```

Запуск миграций:

```sh
npm run db:migrate
```

Создаются таблицы:

- `app_users`;
- `metadata_profiles`;
- `processing_batches`;
- `schema_migrations`.

Фотографии в PostgreSQL не сохраняются. База предназначена для пользователей, профилей и статусов обработки.

## Облачный деплой

Основная выбранная платформа — Railway.

Причины:

- поддержка Docker;
- возможность установить ExifTool и FFmpeg;
- PostgreSQL в том же проекте;
- автоматический HTTPS и домен;
- удобное увеличение CPU, RAM и числа реплик;
- возможность позже добавить Redis, worker-процессы и Bucket.

Подготовленные файлы:

```text
Dockerfile
.dockerignore
railway.toml
.env.example
MIGRATION.md
```

Стартовая архитектура:

```text
Railway Web Service + Railway PostgreSQL
```

При росте:

```text
Web API + Redis queue + FFmpeg workers + private object bucket
```

Рекомендуемый тариф для публичного старта — Railway Hobby от 5 долларов в месяц с оплатой фактического потребления.

## Что осталось перед публичным запуском

1. Создать GitHub-репозиторий.
2. Подключить его к Railway.
3. Добавить Railway PostgreSQL.
4. Задать `DATABASE_URL`, `APP_MODE=cloud` и `DATABASE_SSL=false`.
5. Выполнить миграции.
6. Перенести пользовательские профили из `localStorage` в API и PostgreSQL.
7. Добавить регистрацию и вход пользователей.
8. Добавить лимиты запросов и одновременной обработки.
9. Добавить очередь задач при росте нагрузки.
10. Подключить резервные копии базы перед платными пользователями.

## Важное ограничение Linux

На macOS используются системные ICC-профили Display P3 и sRGB. В Linux-контейнере этих файлов может не быть.

Если точное встраивание Display P3 необходимо для облачной версии, потребуется добавить в контейнер совместимый лицензированный ICC-профиль и указать путь через `P3_PROFILE`.
